# wasel-auth — رمز التحقق عبر الواتساب (VerifyWay)

الدخول، الحساب الجديد، ونسيت كلمة المرور كلها تنتهي برمز من 6 أرقام يُرسل على الواتساب.
مفتاح VerifyWay موجود فقط كسرّ في Supabase، لا في التطبيق ولا في الـ APK.

## خطوات التفعيل (بالترتيب)

1. **نسخة احتياطية** من قاعدة البيانات.
2. **SQL Editor** ← الصق وشغّل `supabase/migrations/0021_phone_otp.sql`.
   (يضيف جدولين ودوال فقط، ولا يغيّر بيانات موجودة. آمن للتشغيل مرتين.)
3. **Edge Functions ← Deploy a new function ← Via Editor**
   - الاسم: `wasel-auth` (بالضبط)
   - الصق محتوى `index.ts` كاملاً ← Deploy
   - من إعدادات الدالة: أطفئ **Verify JWT** (الدخول يحدث قبل وجود جلسة؛ الدالة تتحقق بنفسها).
4. **Edge Functions ← Secrets** أضف:
   | الاسم | القيمة |
   |---|---|
   | `VERIFYWAY_API_KEY` | المفتاح **الجديد** بعد إعادة توليده من لوحة VerifyWay |
   | `VERIFYWAY_SENDER_ID` | `WaselApp` (كما يظهر في صفحة "معرف المرسل" باللوحة) |
   | `OTP_PEPPER` | نص عشوائي طويل (32 حرفاً أو أكثر)، لا تغيّره بعد التفعيل |
   | `VERIFYWAY_LANG` | اختياري: `ar` (الافتراضي) أو `en` |
5. **Authentication ← Sign In / Providers**: أطفئ **Allow new users to sign up**
   (الحسابات الجديدة تُنشأ من الدالة فقط بعد التحقق من الرمز).
6. حدّث التطبيقات للنسخة الجديدة.

## ملاحظات

- الحسابات القديمة تنتقل تلقائياً عند أول دخول بالنسخة الجديدة: كلمة المرور نفسها تعمل.
  بعد الانتقال، النسخ القديمة من التطبيق لا تستطيع الدخول لذلك الحساب، لذلك يجب التحديث.
- الحدود: صلاحية الرمز 5 دقائق، 5 محاولات خاطئة، إعادة الإرسال بعد 60 ثانية،
  3 رموز كل 15 دقيقة و10 باليوم لكل رقم، و20 طلباً بالساعة لكل IP.
- إذا رفض المزوّد الإرسال، يظهر للمستخدم "تعذّر إرسال الرمز"، ويُكتب رد المزوّد في
  Edge Functions ← Logs (بدون الرمز نفسه).
- خطأ VerifyWay `1106` يعني أن اسم المرسل غير معتمد لهذا المفتاح، ويجب طلب اعتماده من المزوّد.
